**Content**:

### The Crisis
QR code payments have become ubiquitous, but they've also become a prime target for fraudsters.

### Statistics & Facts
- 📈 **400% Increase**: QR code scams rose by 400% in the last 2 years
- 💰 **$10M+ Lost**: Millions of dollars lost to fake payment QR codes annually in India alone
- 😰 **70% Fear Factor**: 7 out of 10 people hesitate to scan unknown QR codes
- 🎯 **Common Attack**: Fraudsters physically replace legitimate QR codes with fake ones at shops, restaurants, and parking lots

### Real-World Scenarios
1. **Restaurant Scam**: Fake QR code sticker placed over real one on table
2. **Parking Fraud**: Fraudulent QR codes on parking meters
3. **Street Vendor**: Unverified merchants with no accountability

**Current Problem**: No way to verify if a QR code belongs to a legitimate, registered merchant before making payment.

### Security Architecture

**Multi-Layer Security**:

1. **Authentication Layer**
   - Firebase Authentication with email verification
   - Role-based access control (RBAC)
   - Protected routes with client-side guards

2. **Database Security**
   - Firestore Security Rules
   - User-specific data access
   - Admin-only operations
   ```javascript
   // Example Security Rule
   match /shops/{shopId} {
     allow read: if true;
     allow create: if request.auth != null 
                   && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.status == 'approved';
     allow update, delete: if request.auth != null 
                            && resource.data.ownerId == request.auth.uid;
   }
   ```

3. **QR Code Security**
   - Unique tokens (UUID v4) - 128-bit random identifiers
   - Token regeneration capability
   - Shop enable/disable controls
   - Token validation on every scan

   - XSS protection
   - CSRF protection via Firebase
   - Secure token handling (no localStorage for sensitive data)

5. **Network Security**
   - HTTPS only (enforced by Firebase Hosting)
   - Content Security Policy (CSP)

### Data Flow Architecture

**QR Code Verification Flow**:
```
1. User scans QR code
   ↓
2. Extract token from URL
   ↓
3. Query Firestore: shops collection
   ↓
4. Check: token exists? shop enabled? owner approved?
   ↓
5. Return: Verified ✅ or Unverified ❌
   ↓
6. Display merchant details or warning
```

**Vendor Registration Flow**:
```
1. User registers → Firebase Auth
   ↓
2. Create user document → Firestore (status: pending)
   ↓
3. Admin reviews → Admin dashboard
   ↓
4. Admin approves → Update status: approved
   ↓
5. Vendor can create shops → Generate QR codes
```

- **Animations**: Suggest slide transitions (fade, slide)

- Same header/footer on all slides

- Uniform spacing and alignment
- Professional color palette throughout
